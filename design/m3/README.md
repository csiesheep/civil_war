# M3 ① 牌桌 mockup(#43)

手機 390 × 844、直式、用真的引擎局面畫。**不是可以玩的頁面**:按鈕有的會動(選牌、換用法、換目標、選回應),但都不會把任何動作送回引擎。
`design/` 不在 `public/` 底下,不會被部署。

## 怎麼看

```
node design/m3/states.mjs                 # 重新跑局面,寫 state-a..d.json(約 1 分鐘)
node <任何靜態伺服器> 從 repo 根目錄       # 頁面用 ES module 與 fetch,不能用 file://
  /design/m3/a.html  b.html  c.html  d.html     # 加 ?shot 會靠左(截圖用)
  /design/m3/zoom.html                    # A 的地圖放大 1.8 倍,看最擠的東北與華北
```

在頁面的 console 打 `audit()`(`audit.mjs`)會回報:有沒有橫向捲動、小於 44 × 44 的按鈕、對比低於 4.5:1 的字。

截圖在 `shots/`(2× 像素,390 × 844 的版面):`a.png b.png c.png d.png zoom-northeast.png`。

## 局面從哪來

`states.mjs`:`E.createGame(seed)`,**預設規則**(沒有任何選項),`bots.decide(view, side, "normal", rng)` 兩邊都用 normal,存 `E.view(st, 玩家那一方)` 與 `E.legal(st, 那一方)`。

| 張 | seed | 時點 | 玩家 |
|---|---|---|---|
| A | 27 | 第 5 回合、行動回合 2 | 共軍 |
| B | **34** | 第 4 回合、行動回合 2,共軍宣告打北平 | 國軍 |
| C | 27 | 第 5 回合剛結算完(第 6 回合開頭),摘要是第 5 回合的 log | 共軍 |
| D | 27 | 第 8 回合,共軍民心勝 | 共軍 |

- A 的挑法:第 5 回合、手牌 ≥ 6 的共軍行動回合裡,孤城 / 圍城最多的那一刻;牌是「東北冬季攻勢」(五種用法都合法)。「按了這張牌」是 `states.mjs` 的選擇,不是引擎的(`meta.selectedCard`)。
- **B 不能和 A 同一局**:掃 seed 1..140(normal 對 normal、預設規則),國軍答圍點打援時有「增援」可選的只有 4 局(25、34、78、126),各一次,都在第 3 或 4 回合。原因在 `reinforceSources`:要「補給中、沒被圍、與目標相鄰(或隔一個非共軍的鄉)」的國軍城,而第 4 回合起孤城就很多(seed 27 的第 5 回合是 5 座)。B 用 seed 34 的那一刻(固守 / 增援天津 1 點 / 突圍天津 / 突圍察綏);那一局在第 5 回合就國軍勝,所以 A、C、D 另用 27。**這件事值得 BE / owner 看**:預設規則下,「增援」大概一整局一次都按不到。
- 局面全部在 JSON 裡;頁面只讀 JSON 與引擎(`SPACES`、相鄰、牌、`REGIONS`、`controller`、`isolatedCities`、`besieged`、`SIEGE`、`MANDATE_*`、`homeCapital`),不手抄引擎的資料。

## 版面

地圖是 7 欄 × 10 列的格子(欄距 54、列距 52),節點 46 × 46,節點之間留 6–8 px。每個據點:名字在上,**左紅右藍兩顆數字章(14 px 粗體,零也畫出來,空框)**;誰控制 = 底色與外框(紅 / 藍 / 無);城是雙框方塊,鄉是斜紋圓角方塊;壓在上緣的標籤:右邊是記號(★ 要衝、根 根據地、港、都 首都、勢力的字、◎ 本據;整編 / 易幟的勢力本據標籤變藍 / 紅底),左邊是狀態(孤 = 孤城、圍 = 圍城,同時有就並排縮小)。孤城另外是虛線外框,圍城是紫框。只有格子(`LAYOUT`,位置)是這個 mockup 加的;據點、相鄰、記號全來自 `board.js`。

整個畫面 = 上方 44 px 狀態列 + 524 px 地圖 + 下方 276 px。

| | 狀態列 | 地圖(524) | 下方(276) |
|---|---|---|---|
| A | 第幾回合 · 時期 · 年 / 行動回合 · 對手手牌 · 牌庫 · 棄牌 / 輪到誰 | 軌道在西北角、時局與勢力在西南角、紅框 = 進攻的合法目標、金色粗框 = 選定目標 | 行動面板(牌名、事件、五種用法、取消、目標與打點 / 打援、確定)+ 手牌 5 欄 × 2 列(含外援牌) |
| B | 同上,輪到國軍 | 同上;紅虛線框 = 共軍來處,藍框 = 增援 / 突圍的去處,金框 = 被打的城 | 宣告(攻擊力 X)、引擎給的四個選項、選中那個在兩種共軍計畫下會怎樣、確定 |
| C | 「第 5 回合 結算」 | 同上;金框 = 這回合孤城掉點的城 | 民心與記分、孤城掉點、民生與首都、進入下一回合 |
| D | 「終局」 | (沒有地圖)勝者橫幅、民心曲線(從 log 的 `vp` 重建)、各區控制數、縮小的終局棋盤、三個按鈕 | |

為什麼這樣排:
- **軌道放在地圖西北角**:東北以西、華北以北沒有據點,正好空 262 × 104 px;放在那裡,畫面不必多一條橫帶,地圖才保得住 524 px。西南角(後方的西邊)同理放時局與五個勢力。
- **手牌 5 × 2 而不是橫捲**:每張 72 × 46,最多 10 格(手牌上限 9,另有外援牌),都在拇指區,沒有水平捲動。名稱完整寫在面板標題;牌上的名稱最多兩行。
- **行動面板在手牌上方**:選的牌在下、它的用法在上,拇指從下往上。

## 擠的地方、拿掉的與沒做的

1. **數字與記號的字很小**:名字 10–13 px(三字 11、四字以上 10),記號 11 px(兩個狀態並排時 10 px)。節點只有 46 × 46:放得下兩個數字,是靠把名字、記號縮小換來的。
2. **鄉不是圓,是大圓角方塊**(原 A 版是圓):46 px 的正圓底部放不下兩顆數字章。
3. **A 版的「鐵路 / 小路」兩種線沒有保留**:引擎的相鄰沒有這個資料。這裡城接城畫實線、其餘虛線(由 `kind` 推出來),只是視覺,不是規則。要保留就得 BE 在 `board.js` 加資料。
4. **沒有畫補給源與補給線**(只有「孤」標籤)。港與首都的記號在,補給是否連得上要看標籤。
5. **A 只畫了「進攻」那條路**:扶植 23 處、說客 13 處、進攻 16 處都是合法目標,把全部圈起來太亂,扶植該是「點一個據點、加減點數」的另一種面板,**沒畫**(要 owner 選樣式)。
6. **B 沒有手牌**:決定面板佔了手牌的位置,手牌這一刻不顯示(國軍有 7 張)。
7. **B 的「若是打點 / 若是打援」是我用引擎的 `SIEGE` 常數在頁面裡算的文字**,不是引擎的輸出;真的頁面該向引擎(BE)要一個乾跑,別在 FE 重算規則。
8. **C 沒有逐張牌的回放**,只有 log 裡能直接切出來的:記分、民心、孤城掉點、民生、首都。**民心被上限擋住**這件事(`vp` 的 n 是 −2,但 `mandate` 沒動)引擎沒有欄位,頁面是用前後值算出來標「擋在上限」的。
9. **D 的民心曲線、C 的民心前後都是從 log 的 `vp` 重建**;引擎沒有「每回合民心」的欄位。
10. **事件文字最多兩行**:牌文最長 63 字,面板一行約 31 字,所以 72 張裡約 17 張要用到第二行,最長的一張(63 字)可能被截掉最後一兩個字。(沒有「展開」鈕。)
11. **標題列的 ☰ 沒有內容**(規則、圖例、設定的入口):圖例沒畫,見上面 1、3。
12. **對手的外援(美援)是否已用、勢力的態度、E / C 的軌道**:沒畫(brief 明說 E / C / D 不做)。
13. **只在 390 × 844 驗過**。格子寬 378:寬 360 的手機(很多 Android)東邊一欄會超出 20 px;高度不足 844(例如 667)下方會被推出螢幕、要垂直捲動。這兩個我**用算的,沒有在瀏覽器裡驗**(預覽窗撐不住 360)。要支援就得選:地圖整張縮放(節點變 42 px,低於 44 px 的點按目標)、或欄距縮小(數字章要縮)、或地圖可捲動。

## 要 owner 選的(我沒有定)

- 軌道放地圖西北角(現在)還是一條橫帶(畫面少 524 → 約 470 px 的地圖?)。
- 數字與記號的字大小:現在的密度,或節點放大、欄數縮減(要換地圖的形狀)。
- 孤城的表示法:現在是「孤」標籤 + 虛線框;bot 局裡第 5 回合 17 座城有 5–10 座是孤城,畫面上會一片「孤」。
- 要不要保留鐵路 / 小路兩種線(要 BE 加資料)。
- 手牌:5 × 2 格(現在)、橫向捲動、或疊牌展開。
- 扶植的操作樣式(上面 5)。
- B:決定面板要不要把手牌留在畫面上;要不要顯示結果預覽(7)。
- C:要不要列這回合的逐張牌;「擋在上限」要不要說出來(8)。
- 時局的一句話(我是照引擎的行為寫的,放在 `lib.mjs` 的 `SIT_TEXT`,之後該進語言檔,writer 的)。
- 所有畫面上的字都寫死在 `lib.mjs` / 各頁(`REASON_ZH`、`USE_ZH` ⋯⋯),**只有中文**,之後要進語言檔(兩種語言)。

## 證偽(我自己看過、量過的)

在 390 × 844 的畫面(`Browser` 窗的預覽,與 headless Chrome 兩種):

- **橫向捲動**:四張都沒有(`scrollWidth` = 390)。
- **44 × 44**:四張裡所有的 `<button>`(29 個據點 46 × 46、手牌 72 × 46、面板按鈕 ≥ 44)都 ≥ 44 × 44;D 的縮小棋盤是 `div`,不可點。
- **對比 4.5:1**:四張的字全部過(`audit()`;漸層底用最暗的一格算,是最壞情形)。區域名(東北⋯)原本是 4.1,已改深。
- **29 個據點**:四張各 29 個節點,每個兩顆數字章;用 JS 把頁面上每個節點的兩個數字與 JSON 的 `view.inf` 逐一比對,四張共 116 個,0 個不符。
- 三個據點(紅 / 藍):

  | 據點 | A | B | C | D |
  |---|---|---|---|---|
  | 北平 | 0 / 3 | 0 / 4 | 0 / 2 | 1 / 0 |
  | 天津 | 3 / 0 | 1 / 4 | 3 / 0 | 5 / 0 |
  | 冀魯豫 | 4 / 1 | 0 / 0 | 4 / 1 | 4 / 0 |

- 最擠的一角:`shots/zoom-northeast.png`(東北與華北,放大 1.8 倍)。看得到:孤 + 圍 + ★港 三個標籤同時在錦州、兩顆數字章與名字不重疊、相鄰節點間的 6–8 px。
